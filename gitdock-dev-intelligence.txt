================================================================================
BUGS CRITIQUES (7)
================================================================================

BUG-01 | API Gateway — ai-service sans uri
  Fichier  : gitdock-gateway/src/main/resources/application.yml
  Problème : La route /api/v1/** n'a pas de uri: défini. Le gateway crash ou renvoie 500
             sur tout appel à /api/v1/**.
  Fix      : Ajouter uri: http://localhost:8000 dans la config de ai-service.

BUG-02 | gitdock-sentinel .env — APP_NAME=gitdock-yam
  Fichier  : gitdock-sentinel/.env
  Problème : Sentinel s'enregistre sur Eureka sous le nom "gitdock-yam".
             Deux instances "gitdock-yam" sur Eureka → routing imprévisible.
  Fix      : Corriger APP_NAME=gitdock-sentinel dans .env.

BUG-03 | Frontend .env — ligne JS invalide
  Fichier  : gitdock-frontend/.env
  Problème : La dernière ligne est du code JavaScript :
             const AI_API = import.meta.env.VITE_AI_API_URL || 'http://localhost:8080/api/v1'
             Ce n'est pas du .env valide. Vite ignore cette ligne.
             VITE_AI_API_URL n'est donc jamais défini. Le fallback code-side pointe sur
             /api/v1/** qui est la route BROKEN (BUG-01).
  Fix      : Remplacer par VITE_AI_API_URL=http://localhost:8000 (port réel de gitdock-ai).

BUG-04 | CommitRadar.vue — WebSocket Sentinel hardcodé
  Fichier  : gitdock-frontend/src/views/sentinel/CommitRadar.vue
  Problème : const WS_URL = 'ws://ubuntu-host:8010/api/ws/sentinel' est hardcodé.
             Cassé pour tout développeur hors réseau Tailscale.
  Fix      : Externaliser en VITE_SENTINEL_WS_URL dans .env.
             const WS_URL = import.meta.env.VITE_SENTINEL_WS_URL || 'ws://ubuntu-host:8010/api/ws/sentinel'

BUG-05 | gitdock-ai — Middleware CORS commenté
  Fichier  : gitdock-ai/main.py
  Problème : Toute la section CORSMiddleware est commentée. Le frontend reçoit
             une CORS error bloquante sur toute requête vers localhost:8000.
  Fix      : Décommenter le middleware CORS et restreindre allow_origins à ["http://localhost:5173"].

BUG-06 | vite.config.js — Proxy bypass le Gateway
  Fichier  : gitdock-frontend/vite.config.js
  Problème : proxy '/api' → http://localhost:8083 (Project service direct).
             Si VITE_API_BASE_URL est bien défini dans .env, ce proxy n'est pas
             utilisé par api.ts. Mais si .env est absent ou mal chargé, tous les
             appels /api/* vont sur le Project service en bypassant auth, tasks,
             gamification et notification.
  Fix      : Corriger la cible du proxy vers http://localhost:8080 ou supprimer le proxy.

BUG-07 | gitdock-yam — Eureka enregistre le mauvais port
  Fichier  : gitdock-yam/src/core/config.py
  Problème : app_port=8010 (valeur par défaut pour Eureka) mais main.py lance
             uvicorn sur le port 8012. Eureka dit que YAM est sur :8010 alors
             qu'il écoute sur :8012. Le gateway utilisant une URL directe (:8012),
             le service fonctionne mais Eureka est faux.
  Fix      : Corriger app_port=8012 dans config.py ou définir APP_PORT=8012 dans .env.


================================================================================
AVERTISSEMENTS (6)
================================================================================

WARN-01 | API Gateway — Routes gamification manquantes
  Les endpoints /api/contributors/**, /api/user-progress/**, /api/user-badges/**,
  /api/leaderboard/** ne sont pas routés dans application.yml.
  Résultat : 404 depuis le frontend en passant par le gateway.
  Fix : Ajouter ces paths dans la route gamification-service.

WARN-02 | API Gateway — /api/progress non routé
  VITE_API_PROGRESS_URL=http://localhost:8080/api/progress dans .env frontend
  mais aucune route /api/progress/** dans le gateway.
  Fix : Ajouter la route ou corriger la variable frontend.

WARN-03 | gitdock-auth — GitHub OAuth secrets hardcodés
  client-id et client-secret GitHub présents en clair comme valeurs par défaut
  dans application.yml. Risque de sécurité si le fichier est versionné.
  Fix : Forcer via .env : GITHUB_CLIENT_ID et GITHUB_CLIENT_SECRET sans valeur par défaut.

WARN-04 | gitdock-sync — Kafka bootstrap IP hardcodée
  Valeur par défaut KAFKA_HOST=ubuntu-host dans application.yml.
  Sans variable d'env KAFKA_HOST définie, Kafka est injoignable hors réseau Tailscale.
  Fix : S'assurer que KAFKA_HOST=ubuntu-host est dans le .env de gitdock-sync.

WARN-05 | gitdock-project — RabbitMQ absent de application.yml
  Aucune section spring.rabbitmq dans le fichier de config.
  Soit la config est dans une classe @Configuration Java, soit elle est manquante.
  À vérifier dans RabbitMQConfig.java.

WARN-06 | api.ts — Double interceptor request.use redondant
  Deux interceptors s'enchaînent : le premier lit le token depuis Pinia (authStore),
  le second relit depuis localStorage. Le second peut écraser le premier.
  Fix : Supprimer le second interceptor (localStorage) et conserver uniquement celui
  basé sur Pinia.
